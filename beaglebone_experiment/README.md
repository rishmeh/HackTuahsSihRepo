# Table Tot — BeagleBone Black peripheral experiment

This is an **isolated experiment**.  It does not replace, modify, or start the
Raspberry Pi implementation in `hardware/`.

The laptop remains the only place that performs face recognition, speech,
chat, storage, and application logic.  This folder makes a BeagleBone Black
Rev C act only as a USB-camera, HDMI-face-display, and two-servo peripheral
bridge.

## Confirmed PRU pin mapping

| Robot part | BBB header pin | PRU mapping | Firmware state word |
|---|---:|---|---:|
| Head MG90S signal | **P9_31** | PRU0 `__R30` bit 0 | word 1 |
| Body servo signal | **P9_29** | PRU0 `__R30` bit 1 | word 2 |

`P9_31` is exactly the connection you specified.  It is configured in
`pruout` mode; do not use it for SPI or audio while this experiment runs.
P9_29 is the adjacent PRU0 output chosen for the second servo.  Both outputs
are generated by the same PRU0 firmware, so their pulses start together and
do not depend on Linux scheduling.

## Wiring — power disconnected while wiring

| Part | Wire | Connect to |
|---|---|---|
| Head MG90S | orange/yellow signal | **P9_31** |
| Body servo | orange/yellow signal | **P9_29** |
| Both servos | brown/black ground | external 5 V supply GND |
| BBB ground | one GND jumper | P9_1 or P9_2 to the same external supply GND |
| Both servos | red positive | external regulated 5 V supply positive only |
| USB webcam | USB cable | BBB USB-A host port; use a powered hub if required |
| ST7789 SPI display | VCC | P9_3 (3.3 V) or P9_5 (5 V) — check your panel |
| ST7789 SPI display | GND | P9_1 |
| ST7789 SPI display | SCL/SCK | P9_22 (SPI0_SCLK) |
| ST7789 SPI display | SDA/MOSI | P9_18 (SPI0_D1) |
| ST7789 SPI display | RES/RST | P9_13 (GPIO) |
| ST7789 SPI display | DC/RS | P9_12 (GPIO) |
| ST7789 SPI display | CS | P9_17 (SPI0_CS0) |
| ST7789 SPI display | BL/LED | P9_14 (GPIO) or tie to VCC |
| Laptop link | Ethernet | BBB RJ45 and laptop on the same trusted LAN |
| BBB power | 5 V barrel supply | BBB barrel jack, recommended for camera/display use |

```text
External regulated +5 V -------+---- head MG90S red
                               +---- body servo red

External supply GND -----------+---- head MG90S brown/black
                               +---- body servo brown/black
                               +---- BBB P9_1 or P9_2 (GND)

BBB P9_31  ------------------------- head MG90S signal  (PRU0 R30 bit 0)
BBB P9_29  ------------------------- body servo signal  (PRU0 R30 bit 1)

BBB P9_22 (SPI0_SCLK)  ------------- ST7789 SCL/SCK
BBB P9_18 (SPI0_D1)   ------------- ST7789 SDA/MOSI
BBB P9_17 (SPI0_CS0)  ------------- ST7789 CS
BBB P9_13 (GPIO)      ------------- ST7789 RES/RST
BBB P9_12 (GPIO)      ------------- ST7789 DC/RS
BBB P9_14 (GPIO)      ------------- ST7789 BL/LED (optional)
```

Never connect the external servo supply positive lead to a BBB header 5 V or
3.3 V pin.  The BBB GPIO/PRU outputs are 3.3 V logic; MG90S control inputs
normally accept that level, but verify the exact servo's data sheet if it is a
clone.  Use a regulated 5 V supply with enough stall-current headroom (3 A is
a sensible starting point for two MG90S units) and fit a 470–1000 uF capacitor
across the servo rail close to the servos.  The shared ground is mandatory.

The current display renderer is for an ST7789 4-wire SPI IPS panel.  Do not
attach an HDMI display to the BBB headers under this experiment without a
separate display driver and pin plan.

## Data flow

```text
USB webcam --JPEG frame--> BBB Python bridge --HTTP--> laptop /hardware/process-frame
laptop face-recognition result --JSON command--> BBB bridge --shared PRU RAM--> PRU0 PWM
laptop face state -----------------------------> BBB Pillow renderer --> ST7789 SPI display
```

The bridge uploads a 640x480 JPEG about twice per second.  The laptop returns
the face state and servo state in the same response; the BBB also polls the
laptop state endpoint every 250 ms as recovery.  No face image database,
model, microphone, or speaker runs on the BBB.

## One-time BBB preparation

Use a current BeagleBoard Debian image with the PRU tools/cookbook installed.
The PRU firmware Makefile intentionally reuses the official cookbook Makefile
at `/opt/source/pru-cookbook-code/common/Makefile` rather than hiding any
firmware-loading behavior.

```bash
sudo apt update
sudo apt install -y python3-opencv python3-pygame python3-httpx python3-spidev python3-pil
cd ~/TableTot/beaglebone_experiment
cp .env.bbb.example .env.bbb
```

Set `LAPTOP_URL` in `.env.bbb` to the laptop's LAN IP.  On the laptop, start
the normal service first with `bash run.sh`; allow TCP 8000 on its trusted
private-network firewall.

Compile and load the PRU firmware, configure the SPI display pins, then start
the bridge:

```bash
cd ~/TableTot/beaglebone_experiment
sudo bash scripts/install_pru_firmware.sh
sudo bash scripts/setup_spi_display.sh
sudo bash run.sh
```

The `sudo` requirement is deliberate: the Python bridge maps the documented
PRU shared RAM through `/dev/mem` so it can update pulse widths without
stopping the real-time PRU firmware.  The install script first configures
P9_31 and P9_29 as `pruout`, compiles `servo_pwm.pru0.c`, and loads it through
remoteproc.  It will stop with an error instead of guessing if the expected
cookbook installation is absent.  The setup_spi_display.sh script configures
the SPI0 pins (P9_17/18/21/22) and GPIO control pins (P9_12/13/14) for the
ST7789 display and loads the BB-SPIDEV0 device-tree overlay.

## Safe bring-up sequence

1. Disconnect the servo **red** wires and run `sudo bash scripts/install_pru_firmware.sh`.
2. Confirm both pins report `pruout` and run `sudo python3 test_pru_servo.py --neutral`.
3. Attach only the head servo and test `--head-left`, then `--head-right`.
4. Attach only the body servo and test `--body-left`, then `--body-right`.
5. Attach both, start the laptop service, then run `sudo bash run.sh`.
6. Confirm a recognized face makes the IPS face happy and produces the short
   head/body recognition gesture.  Stop with Ctrl-C; the bridge commands
   neutral before exit.

Start at the conservative pulse limits in `.env.bbb`.  Reverse motion or
mechanical binding means adjust the software direction/limits; do not force a
servo against a hard stop.

## Important constraints

- USB camera only.  A Raspberry Pi CSI camera and cable do not connect to a
  BeagleBone Black.
- ST7789 4-wire SPI IPS display only in this experiment.  The BBB's HDMI
  connector is unused; the face is rendered on the SPI panel.
- PRU firmware assumes a 200 MHz PRU and targets a 20 ms servo frame. Measure
  the output with a scope before changing servo mechanical limits.
- This uses P9_29/P9_31 exclusively as PRU outputs.  Do not enable competing
  SPI, audio, GPIO, or cape overlays for those pins.
- SPI0 pins (P9_17/18/21/22) and GPIO control pins (P9_12/13/14) are used
  exclusively for the ST7789 display.  Do not enable competing overlays.

The official BeagleBoard PRU cookbook documents that P9_31 is PRU0 `__R30`
bit 0 and uses `config-pin P9_31 pruout` for its PWM example.  It also shows
the standard remoteproc firmware flow.  See [the PRU cookbook PWM
example](https://docs.beagle.cc/books/pru-cookbook/05blocks/blocks.html) and
[the configuration guide](https://docs.beagleboard.org/books/pru-cookbook/03details/details.html).
